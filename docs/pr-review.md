## 回归验证

- 单元测试 63 项、124 个断言；新增失败依赖、服务契约失效、历史密钥脱敏、清空后的旧表单、配置版本倒退、迁移预览与并发提交、连接组更名、无关新必填项、完成登记中断、卸载重试/包替换、等待库依赖及人工完成指纹校验、迁移预览变化使确认失效、隐藏暂存恢复副本不参与安装扫描。
- tests/build_review_fixtures.py 生成确定性 ZIP；tests/review_recovery.php 分阶段在独立 MySQL 8.4 / PostgreSQL 17 宿主运行。阶段必须各用新 PHP 进程，避免已加载迁移类影响结果。
- 复现阶段：install → fail_upgrade → retry_upgrade → finalize_interrupted → fail_uninstall → retry_uninstall → config_downgrade → config_migration_fail → config_migration_commit_fail → config_migration_retry → missing_staging_upgrade → legacy_sql_upgrade。最后一项仅 MySQL，PG 明确跳过 SQL-only 包。
- 配置迁移夹具需宿主注册纯 callable：旧 endpoint 更名为 address，保留 apiKey；runtime/review-migration-fail 存在时抛异常。drain 仅对这些无后台业务的隔离夹具返回 true。绝不可对生产配置照抄此排空策略。
- 复审后的在线检测、下载校验、确认与重复确认还通过原 updates_http.php 流程复测，验证并未回退为自动安装。

## 恢复边界

失败取消只解除任务阻塞，不等于回滚业务库或恢复旧代码。未知中断仍必须核对实际文件、迁移日志和 SQL/种子执行情况后，由管理员选择恢复动作。已有升级前文件备份与加密配置历史均不构成数据库回滚点；未提供跨数据库、文件和 Composer/npm 的原子回滚。自定义迁移/探测器必须遵守无副作用、限时和脱敏契约；未实测真实付费商店下载或生产升级。
